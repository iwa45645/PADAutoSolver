# 最優先命令: 先にボックスを検査する

過去の会話に登場したノーチラス、シルヴィ、禰豆子などを、確認なしに最終編成へ固定しないでください。

以下の順番を厳守してください。

1. ボックス走査機能を実装する
2. 利用者のモンスターボックスを先頭から末尾まで一度取得する
3. 重複ページ・重複行を除去する
4. 所持モンスター一覧を`box_inventory.json`として出力する
5. 認識が不確実な候補だけ利用者確認へ回す
6. 裏修羅編成候補に使うモンスターの詳細画面を検査する
7. レベル、スキル、覚醒、超覚醒、潜在、アシスト、変身形態を確認する
8. 裏修羅の攻略要件とスキルスケジュールを照合する
9. 所持個体だけで最大3つの編成候補を生成する
10. 各候補の不足、必要育成、自動化難度、スキル表を示す
11. 利用者が選んだ1編成を`team_profile.json`へ固定する
12. その固定編成を対象に完全自動化を進める

実際のボックスデータがまだない場合、モンスターを推測して設計を完了扱いにしないでください。

ただし、ボックスデータ待ちを理由に作業を止めず、以下を先に完成させてください。

- BOX_SCANモード
- 自動スクロール
- ページ重複除去
- 末尾検出
- inventory JSON
- 不明候補確認UI
- 候補詳細検査フロー
- TeamOptimizerのインターフェース
- SkillScheduleSimulator
- テストfixture作成支援
- 実機で必要な操作手順

その後、利用者が実機で走査できるAPKと、何を確認すべきかを明確に報告してください。

# モンスターカタログ

モンスター同定に外部データを採用する場合、採用前に次を確認してください。

- 実在する入手元
- 取得日またはバージョン
- ライセンス・利用条件
- アイコン・名前・ID・スキル・覚醒などの収録項目
- 更新方法
- 欠落項目
- アプリへの同梱可否

架空のAPI、アクセス不能なURL、利用条件不明の大量スクレイピングを前提にしないでください。

信頼できるカタログがない場合は、次の方式で完成させてください。

- アイコンから複数候補を出す
- 名前や番号のOCR候補を併用
- 利用者が最終確定する
- 確定済み対応表をローカル保存する

不明なアイコンを近い別モンスターへ勝手に確定しないでください。

# 編成評価

編成は火力だけで決めないでください。

ハード制約:

- 実際に所持
- 同じ個体の二重使用なし
- 助っ人を用意可能
- 変身までのスキブ
- 封印、バインド
- 覚醒無効・消せない回復
- ダメージ吸収・属性吸収
- ダメージ無効
- ロック・盤面生成
- 必要HP・軽減・回復
- スキル遅延
- 必要階層までのスキルターン
- アシストが溜まり過ぎない
- ソルバーが安定して組める発動条件

ソフト評価:

- 自動パズルの簡単さ
- 欠損率
- スキル余裕
- 回復安定性
- ボス分岐対応
- 認識の安定性
- 必要な特殊分岐数
- 育成・付け替えコスト
- リプレイ試験成功率

実測前に架空のクリア率を出さないでください。
